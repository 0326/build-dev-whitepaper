# 独立读者测试

独立读者测试验证文章是否能在没有作者上下文的情况下帮助读者作出正确判断。它补充来源核验和结构审计，不能替代它们。

## 什么时候运行

文章完成初稿、准备从 draft 改为 reviewed 前运行。版本更新时，只对新增或受影响的文章重新测试；文章的来源、前置概念或主问题发生变化时，重新运行全部测试。

## 测试输入

为每篇文章建立一个不可变测试快照，至少包含：

- 当前文章正文和 frontmatter；
- 文章声明的适用版本；
- 文章明确链接的前置文章，或明确声明前置内容不需要；
- 文章引用的官方来源标题和链接；
- 本次测试的文章 ID、来源 commit 和测试时间。

不要把作者的研究记录、评审讨论、未公开实现或答案提示交给读者。读者只能使用快照中的内容。

## 五个标准问题

按文章类型调整问题，但至少覆盖以下五类：

1. **定位**：这篇文章解决什么问题，适用于什么版本和场景？
2. **机制**：沿文中的示例，输入经过了哪些关键状态和责任边界？
3. **选择**：给定两个场景，应该选择哪条路径，依据是什么？
4. **失败**：如果指定步骤失败，最先检查哪里，谁负责恢复？
5. **证据**：哪一个结论是官方事实，哪一个是推断或建议？能否找到对应来源？

实践验证文章还要让读者复述成功标准；迁移文章还要让读者列出迁移动作和回退条件。

## 读者输出格式

要求独立读者为每个问题返回：

~~~json
{
  "question_id": "mechanism",
  "answer": "读者自己的回答",
  "confidence": "high",
  "evidence": ["文章章节或来源链接"],
  "uncertainties": ["仍不清楚的地方"]
}
~~~

另附：

~~~json
{
  "contradictions": [],
  "undefined_terms": [],
  "assumed_context": [],
  "overall": "pass"
}
~~~

读者的答案要保留原文，不能只记录一个分数。答案中出现与正文或来源冲突的内容时，记录具体句子和文章位置。

## 判定规则

- **单题通过**：答案覆盖问题要求，引用的证据与结论对应，没有把未知写成事实。
- **关键失败**：机制、边界或证据问题答错，或读者无法区分产品保证与部署方责任。
- **整体通过**：所有关键问题通过，且普通问题通过率至少为 80%；没有未记录的矛盾或关键术语缺失。
- **无法测试**：没有独立读者、快照不完整或环境不可用时，保持 reader-test-unrun，不能写成 reviewed。

## 修订闭环

1. 预测真实读者会问的问题，并记录测试版本。
2. 把快照交给没有作者上下文的读者或独立 Agent。
3. 逐题记录答案、证据、误解和不确定性。
4. 将问题归因到文章缺少前提、过程、边界、证据或导航。
5. 修改文章后重新运行受影响的问题；关键失败需要全量重测。
6. 在交付记录中保存测试快照、结果、修订 commit 和仍未解决的限制。

测试通过只说明读者能正确理解声明范围内的内容，不代表产品能力本身正确，也不代表外部链接持续可达。
