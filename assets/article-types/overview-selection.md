# 项目概览与选型

直接回答：项目解决什么问题，适合谁，读者现在应选择什么路径。

## 读者任务

- 主问题：
- 读者读完后能作出的判断：
- 假定的技术背景：
- 适用版本：

## 问题与目标

说明真实场景、现有做法的限制，以及本项目明确要解决的目标。用事实和固定版本来源支撑范围。

## 设计边界

列出目标、非目标、适用前提和部署方必须补足的条件。不要把未核实的能力写成不支持。

## 方案选择

用相同维度比较本项目与相关替代方案：

| 维度 | 本项目 | 方案 B | 方案 C |
| --- | --- | --- | --- |
| 解决的问题 |  |  |  |
| 关键约束 |  |  |  |
| 接入成本 |  |  |  |
| 失败与恢复 |  |  |  |
| 维护成本 |  |  |  |

每项判断都标注事实来源或明确写成工程建议。

## 推荐路径

给出分支条件，而不是只有一个结论：

- 如果……，从……开始。
- 如果……，先阅读……。
- 如果……，不要采用……，原因是……。

## 证据、限制与继续阅读

列出固定版本的官方来源、仍待核实的结论和下一篇文章。不要用本页代替机制、Reference 或教程文章。
